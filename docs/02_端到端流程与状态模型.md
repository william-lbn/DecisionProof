# 端到端流程与状态模型

## 1. 产品决策阶段

原始文档状态：UPLOADED → PARSED → PROCESSED / FAILED。

产品决策状态：

```text
EXTRACTED / SUGGESTED
→ CONFIRMED
→ APPROVED
├→ REJECTED
└→ SUPERSEDED
```

AI 不允许直接创建 APPROVED 决策。

## 2. 工程就绪包

必须至少包含：

- 已批准 Requirement；
- 已批准 Acceptance Criterion；
- 已批准 Outcome Contract。

建议包含：风险、非功能需求、架构决策、依赖、回滚和可观测性计划。

包的 Digest 根据决策 ID 和 Canonical Digest 生成。任何决策修改都必须产生新版本和新工程包。

## 3. 研发阶段

高层 Change Phase：DRAFT、SPEC_REVIEW、SPEC_APPROVED、ARCHITECTURE_REVIEW、PLAN_APPROVED、IMPLEMENTATION_ACTIVE、VERIFICATION_ACTIVE、READY_FOR_RELEASE、RELEASE_ACTIVE、OUTCOME_OBSERVING、COMPLETED、FAILED、CANCELLED、SUPERSEDED。

真实生产实现需要 RepositoryChange、AgentRun、PipelineRun、Artifact、Release、Deployment 子聚合，避免把所有状态塞进单一 Change。

## 4. 证据失效

- MR Head SHA 变化：旧 Review、CI、安全扫描全部 STALE；
- Artifact Digest 变化：旧 SBOM、Provenance、Signature 失效；
- Release Manifest 变化：旧 Release Approval 失效；
- Deployment UID 或 Artifact 变化：旧 Staging/Canary Evidence 失效；
- Product Decision 内容变化：旧人工批准和工程包失效。

## 5. 外部副作用

动作状态：PENDING、EXECUTING、SUCCEEDED、FAILED、UNKNOWN。

UNKNOWN 表示外部系统可能已经提交，但平台没有可靠回执。必须 Read-back：查询 Branch、MR、Merge、Pipeline、GitOps Commit 或 Deployment，不得盲目重试。
