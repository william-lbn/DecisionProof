# 系统架构与前沿 AI 工程

## 1. 架构分层

```text
产品体验层
→ 文档智能与产品知识层
→ 决策、审批和工程基线层
→ Durable Workflow 与 Tool Gateway
→ GitLab/Agent/CI/Registry/GitOps
→ Argo/Kubernetes/Prometheus
→ Evidence Graph/Outcome/Audit
```

## 2. Agent 中立

核心系统只依赖稳定 Agent Task/Event/Result 协议。Codex、OpenHands、企业自研 Agent 和未来 A2A Agent 都是 Provider。

平台保存：模型、Provider、Prompt/Config Digest、工具调用、可观察输出、Token/Cost 和最终结果；不保存或要求模型隐藏思维链。

## 3. Codex 集成

一期推荐两种方式：

1. Agent Runner 中调用 Codex CLI headless；
2. GitLab CI 中进行结构化 Code Review、安全结果归并和 CI 修复建议。

仓库根目录和子模块使用 AGENTS.md 记录可审查的工程规则；确定性规则仍由测试、Lint、策略和分支保护强制执行。

## 4. OpenHands 集成

采用 Remote Agent Server 或隔离 Sandbox，把 OpenHands 作为执行 Provider，而不是权限、状态和证据控制面。

## 5. MCP

MCP 用于暴露 Resources、Prompts 和 Tools，但所有具有副作用的 MCP Tool 必须代理到 Tool Gateway。工具注解、描述和模型生成参数均不可作为可信授权依据。

## 6. A2A

A2A 可用于跨团队和跨厂商 Agent 的任务委派，但 A2A Task/Artifact 只作为协作协议；最终状态、权限和证据仍由 DecisionProof 控制。

## 7. AI 可观测性

采用 OpenTelemetry Trace/Metric/Log，记录：

- Agent Run；
- Model Call；
- Tool Call；
- Retrieval；
- Token 和费用；
- Time to First Token；
- 错误和重试；
- Change、MR、Commit、Release 的关联属性。

OpenTelemetry GenAI 语义仍在快速演进，因此平台应固定内部 Schema Version，再映射到当前 OTel 语义。

## 8. AI 评估

每个 Agent Provider 上线前验证：

- 任务成功率；
- 正确 Patch 比例；
- 测试欺骗率；
- 高风险路径修改率；
- Review Precision/Recall；
- Prompt Injection 成功率；
- 成本和延迟；
- 失败后人工接管时间。

模型升级不能直接替换生产默认模型，必须通过离线 Replay、Shadow 和 Canary。
