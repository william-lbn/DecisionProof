# 安全、证据与软件供应链

## 1. 不可关闭的安全基线

- Agent 不能批准自己、合并 MR 或生产发布；
- Agent 不持有生产和 GitLab Maintainer 长期凭据；
- 未签名、无 SBOM、无 Provenance、Subject 不匹配的制品不能发布；
- 可变 Tag 不能作为发布身份；
- No Data 不能自动推广；
- UNKNOWN 不能盲目重试；
- 高风险变更必须人工批准。

## 2. Evidence V2

每条证据包含 SchemaVersion、SubjectType、SubjectID、SubjectDigest、ProducerIdentity、TrustClass、SourceSystem、SourceURI、ExternalID、PayloadDigest、RecordHash、Supersession 和 Invalidation。

TrustClass：DECLARED、OBSERVED、VERIFIED、ATTESTED、HUMAN_APPROVED。

发布门一般只接受 VERIFIED、ATTESTED 和 HUMAN_APPROVED。

## 3. 供应链

推荐 GitLab CI：测试/扫描 → Rootless BuildKit → GitLab Registry Digest → Syft SBOM → Cosign Signature/Attestation → SLSA/in-toto Provenance → 平台验证。

Provenance 字段必须由受信构建控制面生成或验证，不能让用户定义构建步骤任意注入。

## 4. Agent Sandbox

- 独立 K8s Job；
- Non-root、ReadOnlyRootFilesystem、Drop ALL、Seccomp；
- 不挂载 Docker Socket；
- 不自动挂载 ServiceAccount Token；
- 默认拒绝网络；
- 仅允许 GitLab、模型服务、依赖代理；
- 临时 PVC 和凭据；
- 超时和 TTL 清理；
- 高风险使用 gVisor/Kata RuntimeClass。
