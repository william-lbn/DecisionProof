# 外部技术依据与架构判断

版本日期：2026-07-24

本文件记录架构选择所依据的官方公开资料。链接用于后续研发人员核查当前版本，不代表相关外部能力已经在本仓库中完成真实集成。

## 一、GitLab

- GitLab CI/CD：`https://docs.gitlab.com/ci/`
- GitLab Webhooks：`https://docs.gitlab.com/user/project/integrations/webhooks/`
- GitLab Project Webhooks API 和 HMAC signing token：`https://docs.gitlab.com/api/project_webhooks/`
- GitLab REST API：`https://docs.gitlab.com/api/rest/`
- GitLab Merge Requests API：`https://docs.gitlab.com/api/merge_requests/`
- GitLab Pipeline API：`https://docs.gitlab.com/api/pipelines/`
- GitLab CI Job Token：`https://docs.gitlab.com/ci/jobs/ci_job_token/`
- GitLab Protected Branches：`https://docs.gitlab.com/user/project/repository/branches/protected/`
- GitLab Container Registry：`https://docs.gitlab.com/user/packages/container_registry/`
- GitLab Duo Agent Platform GA（18.8）：`https://docs.gitlab.com/releases/18/gitlab-18-8-released/`
- GitLab 19.0：`https://about.gitlab.com/releases/2026/05/21/gitlab-19-0-released/`

架构判断：GitLab 自身已经进入 Agentic SDLC，因此 DecisionProof 不能以“又一个 GitLab Coding Agent”为主要差异化，而必须提供跨产品决策、独立证据、外部动作结算、软件/Agent Release 和生产 Outcome 的治理层。

## 二、产品发现

- Jira Product Discovery：`https://support.atlassian.com/jira-product-discovery/docs/about-jira-product-discovery/`
- Insights：`https://support.atlassian.com/jira-product-discovery/docs/what-are-insights/`
- AI in Jira Product Discovery：`https://support.atlassian.com/jira-product-discovery/docs/explore-atlassian-intelligence-in-jira-product-discovery/`

架构判断：产品输入、洞察和 Roadmap 已有成熟竞争者。DecisionProof 不应复制完整产品管理套件，而应将来源证据、批准基线、工程事实和生产结果连接起来。

## 三、Durable AI

- Temporal 文档：`https://docs.temporal.io/`
- AI Cookbook：`https://docs.temporal.io/ai-cookbook`
- Human-in-the-loop：`https://docs.temporal.io/ai-cookbook/human-in-the-loop-python`
- OpenAI Agents SDK Durable Agent：`https://docs.temporal.io/ai-cookbook/openai-agents-sdk-python`

架构判断：跨小时、天或月的 Agent 流程、人工审批和外部工具调用应由 Durable Workflow 管理，不能把模型上下文或 LangGraph Checkpoint 当作企业业务事实数据库。

## 四、Agent 执行

- OpenHands SDK：`https://docs.openhands.dev/sdk/`
- Remote Agent Server：`https://docs.openhands.dev/sdk/guides/agent-server/overview`
- Runtime Architecture：`https://docs.openhands.dev/openhands/usage/architecture/runtime`
- OpenAI Codex SDK：`https://developers.openai.com/codex/sdk/`
- Codex GitLab CI 示例：`https://developers.openai.com/cookbook/examples/codex/codex_code_review/`

架构判断：Codex/OpenHands 是可替换的执行 Provider；状态、权限、工具副作用和证据必须由 DecisionProof 掌握。

## 五、MCP 与 A2A

- MCP Specification：`https://modelcontextprotocol.io/specification/2025-11-25`
- MCP Tools：`https://modelcontextprotocol.io/specification/2025-11-25/server/tools`
- MCP Security Best Practices：`https://modelcontextprotocol.io/specification/2025-11-25/basic/security_best_practices`
- A2A Protocol：`https://a2a-protocol.org/`

架构判断：MCP 解决工具和上下文互操作，A2A 解决 Agent 间协作。二者都不是授权、结算和审计系统，不能绕过 Tool Gateway。

## 六、软件供应链

- SLSA Provenance：`https://slsa.dev/spec/v1.2/provenance`
- in-toto：`https://in-toto.io/`
- Sigstore/Cosign：`https://docs.sigstore.dev/`
- Syft：`https://github.com/anchore/syft`

架构判断：Provenance 必须由可信控制面生成并绑定准确 Subject；不能由被构建项目自行填写关键证明字段。

## 七、交付与观测

- Argo CD：`https://argo-cd.readthedocs.io/`
- Argo Rollouts：`https://argo-rollouts.readthedocs.io/`
- OpenTelemetry：`https://opentelemetry.io/docs/`
- OpenTelemetry GenAI：`https://opentelemetry.io/docs/specs/semconv/gen-ai/`
- Prometheus：`https://prometheus.io/docs/`

架构判断：LLM 可以解释和建议，实际流量推进、暂停和回滚应由确定性控制器和策略执行；AI 遥测使用内部版本化 Schema 再映射到快速变化的 OTel GenAI 语义。
