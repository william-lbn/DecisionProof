当前仓库不是完整生产平台，而是已完成 PostgreSQL 单节点 Kubernetes 实验验收的 V2 工程底座。

- 产品资料到结构化决策、人工确认/批准、工程就绪包和 GitLab Bundle 的本地闭环已经实现。
- P0 变更状态机、证据哈希链、Subject Binding、受控外部动作与 `UNKNOWN` 对账语义已经实现。

## 4. 已确认的关键工程问题

### 4.1 运行时与持久化

1. `control-api` 已可按 `SDLC_DATABASE_URL` 选择文件或 PostgreSQL，并统一注入可信租户上下文。
2. Migration CLI、摘要防篡改版本表、核心/产品/Inbox Repository 和数据库 Readiness 已完成。
3. `/healthz` 只表示进程存活；`/readyz` 在数据库不可用时返回 503，已完成真实故障验证。
4. 上传大对象仍使用本地 PVC；文件和 PostgreSQL 两种模式都只适合单副本实验。
5. PostgreSQL 尚无 TLS、连接代理、复制、PITR、备份恢复和自动故障转移。

### 4.2 身份与权限

1. 浏览器可直接提交 `X-Tenant-ID`、`X-Actor-ID` 和角色头。
2. 产品 API 只检查身份头存在，不检查角色权限。
3. 没有 OAuth/OIDC、Session、CSRF 或可信代理签名。
4. 当前工作台不能安全暴露到公网。

### 4.3 数据一致性与审计

1. 产品提取已改为 Repository 原子保存；失败测试证明不会留下部分决策。
2. 上传解析或注册失败会清理临时文件和对象文件。
3. 工程就绪包摘要绑定当时的决策 ID 与 Canonical Digest，但读取仍按 ID 取得当前对象，尚未保存完整不可变快照。
4. 旧 Release Manifest 仍是一条 Change 一份，不能表达重发、回滚和多环境。
5. File/PostgreSQL Inbox 状态已统一；0004 迁移修复历史 `RECEIVED/RETRY` 与待处理索引。

### 4.4 外部闭环

1. GitLab Client 有超时、读重试和写不重试，但没有完整 Tool Gateway Executor 和 Read-back Reconciler。
2. Webhook 只可靠接收，没有后台处理器。
3. CI 报告、制品 Digest、SBOM、Signature、Provenance 没有真实采集验证。
4. Argo 示例不是 Adapter，也不是已执行部署。
5. Agent CLI 不是 Kubernetes 隔离调度器。

### 4.5 运维与交付

1. Helm Chart 当前使用 `Recreate` 且只允许单副本，符合本地对象存储约束。
2. Chart 已有 PostgreSQL Secret、迁移 Init Container 和 `/readyz`，但仍无 PDB、HPA、Ingress、备份和外部数据库精细 NetworkPolicy。
3. Dockerfile 基础镜像和实验 PostgreSQL 镜像已绑定 Registry Digest；本地应用镜像以 Docker Image ID 完成集群验证，正式发布仍需 Registry Digest。
4. 当前目录已初始化 Git，并将在基线验证后把精确提交回读到 GitHub；分支保护仍需仓库管理员配置。
5. 当前全工程覆盖率为 51.4%，低于总覆盖率 75% 的生产候选门槛。

## 5. 分阶段执行计划与验收门

- `/healthz`、UI、上传、提取、批准和工程包在集群内通过。

### 阶段 B：PostgreSQL 可运行底座

交付：

- pgx 驱动与连接池配置；
- Migration CLI、版本记录和幂等迁移；
- 核心与产品 PostgreSQL Repository；
- PostgreSQL Webhook Inbox；
- `/healthz` 与 `/readyz` 分离；
- Helm 中 PostgreSQL 连接、Secret、迁移 Job；
- RLS、重启持久化、并发和失败路径集成测试。

Go/No-Go：

- 默认实验配置使用 PostgreSQL；
- 跨租户读取为零；
- Pod 重启后数据可读；
- 数据库不可用时 `/readyz` Fail-closed；
- migrations、OpenAPI、测试和文档一致。

### 阶段 C：GitLab Truth Harness

交付：

- OAuth/OIDC 或实验环境受控 Token 接入；
- Project Onboarding；
- PostgreSQL Webhook Inbox/Reconciler；
- Issue/Branch/Commit/Draft MR Executor；
- 所有写动作幂等键和 Read-back 对账；
- Disposable GitLab Project Truth Test。

Go/No-Go：

- 真实 GitLab 上完成 Engineering Package → Issue → Branch → Commit → Draft MR；
- 超时、429、重复/乱序 Webhook 不产生重复副作用；
- Agent 无默认分支 Merge 权限；
- Read-back 证据绑定真实 Project/IID/SHA。

### 阶段 D：Durable Workflow 与 Agent Runtime

交付：

- Temporal Change/RepositoryChange/Release Workflow；
- Signal、Query、Activity、Retry 分类和 Versioning；
- Kubernetes Job Scheduler；
- Codex/OpenHands Provider；
- 临时凭据、Workspace、网络策略、预算、取消和 TTL。

Go/No-Go：

- Worker 在关键 Activity 后被杀可恢复；
- Agent Job 非 root、只读根文件系统、无 ServiceAccount Token、无 Docker Socket；
- Agent 只能创建变更和 Draft MR，不能批准、合并或生产发布；
- 真实 Provider Truth Test 与日志脱敏通过。

### 阶段 E：CI、供应链与 Merge Qualification

交付：

- GitLab CI 模板；
- Test/SAST/Dependency/Container Scan；
- Syft SBOM；
- 不可变镜像 Digest；
- Cosign Signature/Attestation 与 Provenance；
- Evidence Ingest 和 API Read-back；
- Merge Qualifier 与受控 Bot Merge。

Go/No-Go：

- 证据 Subject 必须匹配 MR Head SHA 和 Artifact Digest；
- 缺失、过期、篡改或未签名证据全部 Fail-closed；
- Bot Merge 携带当前 Head SHA；
- Agent 和普通开发者不能直接合并默认分支。

### 阶段 F：GitOps、灰度、Outcome

交付：

- V2 多 Release Attempt；
- GitOps MR 和 Read-back；
- Argo CD、Argo Rollouts Adapter；

- Prometheus 技术/业务指标；
- Pause/Promote/Rollback；
- Outcome Contract 和审计包。

Go/No-Go：

- 发布身份只使用 Artifact Digest；
- No Data、策略不可用或证据缺失时 Pause/Fail-closed；
- Canary 故障可自动回滚并保存证据；
- Deployment → Release → Artifact → Commit → Requirement 可追踪。

### 阶段 G：生产化

交付：

- OIDC、KMS/OpenBao、Secret Provider；
- 多副本、PDB/HPA、备份恢复；
- 安全、负载、Chaos、升级回滚；
- 7×24 Soak；
- 运维、部署、使用、灾备和审计手册。

Go/No-Go：

- 总覆盖率不低于 75%，Domain ≥90%、Application ≥85%、Adapter ≥70%；
- Critical/High 安全问题清零；
- 真实备份恢复和升级回滚通过；
- 7×24 无不可恢复 Workflow；
- 第二故障域/第二集群验证完成后才可声明生产就绪。

## 7. 本地集群使用边界

当前 kube-context 为 `docker-desktop`，Kubernetes Server 为 v1.30.5，默认存储类为 `hostpath`。
集群还存在一个与本项目无关的 `NotReady` 节点；DecisionProof 实验工作负载必须：

- 使用独立 namespace；
- 明确调度到 `docker-desktop` Ready 节点；
- 不修改现有 namespace 和工作负载；
- 使用项目专用 Secret、PVC 和 ServiceAccount；
- 部署和清理命令都列出精确资源范围。
