# DecisionProof PostgreSQL 实验部署与使用手册

版本：V2.2 Stage C Experimental
日期：2026-07-24

## 1. 适用范围

本手册部署的是已经真实验证的单集群实验环境：

```text
DecisionProof Control API + Web UI
→ PostgreSQL 元数据与 RLS
→ 本地 PVC 原始文档对象
→ PostgreSQL GitLab Webhook Inbox
```

它可以验证产品资料、来源锚点、决策确认/批准、工程就绪包、P0 控制内核、Webhook 去重和
数据库故障 Readiness，以及 Stage C 的 OIDC/GitLab Contract 代码部署。它尚未完成企业
IdP 或真实 GitLab Provider Truth，也不包含 Temporal、Kubernetes Agent、Cosign、
Argo Rollouts 和生产高可用。

## 2. 前置条件

- Go 1.26.5；
- Docker；
- Kubernetes；
- Helm 3；
- `kubectl` 当前上下文指向实验集群；
- 至少 4 CPU、6 GiB 可用内存和 5 GiB 可用持久存储。

先检查：

```bash
go version

kubectl get storageclass
helm version
```

## 3. 本地验证

```bash
gofmt -w .
go vet ./...
go test ./...
go test -race ./...
make build
```

真实 PostgreSQL Truth Test 需要管理员与非超级用户应用连接串：

```bash
DECISIONPROOF_TEST_ADMIN_DATABASE_URL='postgres://ADMIN_USER:ADMIN_PASSWORD@HOST:5432/decisionproof?sslmode=require' \
DECISIONPROOF_TEST_APP_DATABASE_URL='postgres://APP_USER:APP_PASSWORD@HOST:5432/decisionproof?sslmode=require' \
go test -count=1 -v ./internal/database ./internal/integrations/gitlab
```

未设置连接串时测试会明确 `Skip`，不能把 Skip 写成真实 PostgreSQL 通过。

## 4. 构建不可变本地镜像

```bash
docker build -f deploy/docker/Dockerfile -t decisionproof/control-api:stage-c .
IMAGE_ID="$(docker image inspect decisionproof/control-api:stage-c --format '{{.Id}}')"
docker image inspect "$IMAGE_ID"
```

Docker Desktop Kubernetes 与 Docker 共享镜像存储时，可直接使用 `sha256:...` Image ID 和
`imagePullPolicy=Never`。其他集群必须把镜像推送到受信 Registry，并使用 Registry 返回的
Manifest Digest：

```text
registry.example/decisionproof/control-api@sha256:真实的ManifestDigest
```

不得使用 `latest`，也不得用本地 Tag 充当发布身份。

## 5. 创建隔离 namespace 和签名密钥

```bash
kubectl create namespace decisionproof-experiment

SIGNING_SEED="$(openssl rand -base64 32)"
WEBHOOK_SECRET="$(openssl rand -hex 32)"

kubectl -n decisionproof-experiment create secret generic decisionproof-signing \
  --from-literal=seed="$SIGNING_SEED"
kubectl -n decisionproof-experiment create secret generic decisionproof-gitlab-webhook \
  --from-literal=signing-secret="$WEBHOOK_SECRET"
```

`SIGNING_SEED` 只用于实验。生产必须使用 KMS/Sigstore 受控密钥和轮换机制。

## 6. 部署实验 PostgreSQL

创建管理员与应用账号随机密码：

```bash
ADMIN_PASSWORD="$(openssl rand -hex 24)"
APP_PASSWORD="$(openssl rand -hex 24)"

kubectl -n decisionproof-experiment create secret generic decisionproof-postgres-bootstrap \
  --from-literal=admin-password="$ADMIN_PASSWORD" \
  --from-literal=app-password="$APP_PASSWORD"

kubectl -n decisionproof-experiment apply \
  -f deploy/examples/postgres/experimental-postgres.yaml

kubectl -n decisionproof-experiment rollout status \
  statefulset/decisionproof-postgres --timeout=120s
```

分别创建迁移管理员和非超级用户应用连接串：

```bash
kubectl -n decisionproof-experiment create secret generic decisionproof-database-admin \
  --from-literal=database-url="postgres://decisionproof_admin:${ADMIN_PASSWORD}@decisionproof-postgres:5432/decisionproof?sslmode=disable"

kubectl -n decisionproof-experiment create secret generic decisionproof-database-app \
  --from-literal=database-url="postgres://decisionproof_app:${APP_PASSWORD}@decisionproof-postgres:5432/decisionproof?sslmode=disable"
```

实验清单固定 PostgreSQL Registry Digest，但没有 TLS、备份、PITR、复制或故障转移。

## 7. 安装 DecisionProof

Docker Desktop 本地镜像方式：

```bash
helm upgrade --install decisionproof deploy/helm/decisionproof \
  --namespace decisionproof-experiment \
  --set-string image.repository="$IMAGE_ID" \
  --set-string image.digest= \
  --set image.pullPolicy=Never \
  --set storage.mode=postgres \
  --set database.existingSecret=decisionproof-database-app \
  --set database.migrationExistingSecret=decisionproof-database-admin \
  --set database.migrateOnDeploy=true \
  --set existingGitLabWebhookSecret=decisionproof-gitlab-webhook \
  --set gitlab.tenantID=tenant-demo \
  --set gitlab.integrationID=gitlab-experiment \
  --set-string 'nodeSelector.kubernetes\.io/hostname=docker-desktop' \
  --wait --timeout 120s
```

Registry Digest 方式：

```bash
helm upgrade --install decisionproof deploy/helm/decisionproof \
  --namespace decisionproof-experiment \
  --set image.repository=registry.example/decisionproof/control-api \
  --set image.digest=sha256:REPLACE_WITH_REAL_MANIFEST_DIGEST \
  --set storage.mode=postgres \
  --set database.existingSecret=decisionproof-database-app \
  --set database.migrationExistingSecret=decisionproof-database-admin \
  --set existingGitLabWebhookSecret=decisionproof-gitlab-webhook \
  --set gitlab.tenantID=tenant-demo \
  --set gitlab.integrationID=gitlab-experiment \
  --wait --timeout 120s
```

迁移 Init Container 成功后 API 才会启动。检查：

```bash
kubectl -n decisionproof-experiment get pods,pvc
kubectl -n decisionproof-experiment logs deployment/decisionproof-decisionproof \
  -c database-migrate
kubectl -n decisionproof-experiment logs deployment/decisionproof-decisionproof \
  -c control-api
```

## 8. 访问与角色使用方式

建立本地端口转发：

```bash
kubectl -n decisionproof-experiment port-forward \
  service/decisionproof-decisionproof 8080:8080
```

浏览器打开：

```text
http://127.0.0.1:8080/app/
```

当前实验工作台使用开发身份头，角色操作顺序为：

1. 产品经理上传 Markdown/TXT/DOCX/PPTX；
2. 产品经理执行提取并确认候选决策；
3. 切换为不同的产品负责人批准决策；
4. 至少批准一条 `REQUIREMENT`、`ACCEPTANCE_CRITERION` 和 `OUTCOME_CONTRACT`；
5. 切换为 `delivery_manager` 生成工程就绪包；
6. 审计人员查看工程包 Digest 和 GitLab Bundle。

确认人与批准人相同时 API 会返回 409。当前身份头不能用于公网或生产。

## 10. Webhook 验证

GitLab HMAC 请求头格式：

```text
Webhook-Signature: sha256=<HMAC-SHA256(raw-body, WEBHOOK_SECRET)>
X-Gitlab-Event-UUID: <GitLab Event UUID>
X-Gitlab-Event: <Event Type>
```

相同 Integration 和 Event UUID 重复投递必须返回：

```json
{"accepted":true,"duplicate":true}
```

API Pod 重建后仍应返回相同 `inbox_record_id`，证明去重事实来自 PostgreSQL，而不是进程内存。

## 11. RLS 与故障门验证

非超级用户应用账号在未设置租户上下文时必须看不到业务行：

```bash
kubectl -n decisionproof-experiment exec decisionproof-postgres-0 -- \
  psql -U decisionproof_app -d decisionproof \
  -c 'select count(*) from product_decisions;'
```

数据库不可用时 Readiness 必须返回 503。只在隔离实验 namespace 执行：

```bash
kubectl -n decisionproof-experiment scale statefulset decisionproof-postgres --replicas=0
curl -i http://127.0.0.1:8080/readyz
kubectl -n decisionproof-experiment scale statefulset decisionproof-postgres --replicas=1
kubectl -n decisionproof-experiment rollout status statefulset/decisionproof-postgres --timeout=120s
curl -i http://127.0.0.1:8080/readyz
```

预期分别为 503 和恢复后的 200。

## 12. 升级、回滚与清理

升级前记录 Helm revision 和镜像 Digest：

```bash
helm -n decisionproof-experiment history decisionproof
kubectl -n decisionproof-experiment get deployment decisionproof-decisionproof \
  -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
```

回滚到上一 Helm revision：

```bash
helm -n decisionproof-experiment rollback decisionproof REVISION --wait --timeout 120s
```

迁移只能向前兼容；数据库回滚必须使用经过验证的备份恢复流程，不能假定 Helm 回滚会撤销 DDL。

清理会删除实验 namespace 内的 Deployment、StatefulSet、Secret 和 PVC，数据不可恢复：

```bash
helm -n decisionproof-experiment uninstall decisionproof
kubectl delete namespace decisionproof-experiment
```

执行清理前必须导出需要保留的审计数据和对象。
